# GrantEd CRM

Рабочая версия для владельца и команды до 10 сотрудников. Node.js 24+, SQLite. Интерфейс написан на React + TypeScript + Tailwind CSS и собирается Vite в папку `dist/`; сервер (`server/`) по-прежнему без npm-зависимостей во время работы. Соберите интерфейс командой `npm run build`, запустите сервер командой `npm start` и откройте http://127.0.0.1:4173. Статический HTTP-сервер больше не подходит.

Рекомендуется хранить репозиторий GitHub как **Private**: приложение работает с персональными данными клиентов. Файлы базы, `.env`, резервные копии и локальные скриншоты исключены через `.gitignore`.

## Быстрый запуск из GitHub

```bash
git clone ВАШ_URL_РЕПОЗИТОРИЯ
cd admissions-crm
cp .env.example .env
npm install
npm run build
npm start
```

Откройте `http://127.0.0.1:4173`. Для production-развёртывания на PS.kz используйте [`deploy/pskz/README.md`](deploy/pskz/README.md).

При первом открытии создайте администратора: ваша почта и пароль минимум 12 символов. Первичная настройка доступна только с компьютера сервера. Пароль хранится как scrypt-хеш. Сессия действует 12 часов. База изначально пустая: можно добавить настоящих клиентов либо нажать «Импорт из прототипа» в том браузере, где использовалась старая версия. Импорт переносит все карточки, включая вымышленные, и доступен только в пустую базу. Старый localStorage не удаляется.

## Возможности

- Клиенты: бакалавриат, магистратура, PhD; поиск, фильтры, страницы по 10 записей.
- Команда: до 10 активных сотрудников и ожидающих приглашений, отдельный пароль для каждого, одноразовая ссылка на 7 дней, отключение доступа владельцем.
- Профиль: направление, страны, семестр и год, финансирование, английский, GRE/GMAT, консультант, дата старта, контакты.
- Заявки по вузам, статусы, дедлайны, задачи, внутренние заметки.
- Application fee: сумма, валюта, статус и дата оплаты. Итоги только оплаченных сборов, отдельно по валютам без конвертации.
- WhatsApp: открытие чата по номеру. Прикрепление PDF выполняется вручную; WhatsApp Business API и импорт переписки не подключены.
- Одностраничный PDF по завершении этапа. Итоги, следующий этап, действия клиента, снимок заявок и расходов. До 8 подробных заявок; все заявки учтены в сводке. PDF — изображение высокого разрешения, текст не выделяется. Переполнение блокирует выгрузку.
- Отметки отправки и ознакомления вносятся администратором по фактическому сообщению клиента. Клиентского портала, публичных ссылок подтверждения и автоматической рассылки нет.

## Хранение и восстановление

`data/crm.sqlite` — база клиентов и настроек. Папка закрыта правами файловой системы и исключена из Git. Резервная SQLite-копия создаётся при запуске и затем раз в сутки, сохраняются 14 последних копий. Это локальная копия на том же диске: отдельное внешнее резервирование пока не настроено.

Для полного восстановления остановите сервер, сохраните текущую папку data отдельно, замените crm.sqlite резервной копией и уберите старые crm.sqlite-wal/crm.sqlite-shm из рабочей папки. Храните базу в защищённой резервной копии. JSON-экспорт в боковом меню включает клиентов, заявки и отчёты, но не пароли и токены. Импорт JSON-файла через интерфейс пока не добавлен.

При конфликте между вкладками сервер отклоняет устаревшее сохранение. Интерфейс показывает постоянное уведомление; скопируйте введённый текст и обновите страницу перед повторной правкой.


## Приглашения сотрудников по email

Владелец открывает «Настройки → Команда», указывает имя и рабочую почту сотрудника. Если почтовая отправка настроена, сотрудник получает одноразовую ссылку и создаёт собственный пароль. Если отправка ещё не настроена, CRM показывает ссылку, которую можно скопировать вручную. Активные сотрудники и ожидающие приглашения вместе занимают не более 10 мест. Владелец может отозвать приглашение или отключить сотрудника; отключение сразу завершает его сессии.

Для автоматической отправки используется Resend Email API без дополнительной npm-библиотеки. Подтвердите домен отправителя в Resend, затем добавьте в `.env`:

```text
RESEND_API_KEY=re_...
MAIL_FROM="GrantEd CRM <crm@ваш-домен.kz>"
```

Ключ храните только на сервере и не добавляйте в Git. После изменения `.env` перезапустите CRM. До настройки Resend приглашения создаются корректно, но отправляются вручную по показанной ссылке.

## Публикация

Сейчас сервер доступен только на вашем компьютере. Публичный сайт не развёрнут. Для запуска в интернете нужен сервер с Node 24 и постоянным диском, HTTPS reverse proxy и APP_ORIGIN с вашим доменом. Создайте администратора локально до публикации. При внешнем запуске задайте HOST и PORT по конфигурации reverse proxy; сохраните оригинальный Host. Статический Sites-хостинг не подходит для SQLite/API.

Для домена и VPS в PS.kz подготовлены готовые шаблоны Nginx, systemd и production-переменных, а также пошаговая инструкция: [`deploy/pskz/README.md`](deploy/pskz/README.md).

## Разработка

- `npm run dev` — Vite-сервер с горячей перезагрузкой на http://127.0.0.1:5173; запросы `/api` проксируются на `npm start` (порт 4173), поэтому запустите сервер параллельно.
- `npm run build` — проверка типов TypeScript и production-сборка в `dist/` (`index.html`, `app.js`, `style.css` — эти имена ожидает `server/index.mjs`).
- `npm run typecheck` — только проверка типов.

Структура интерфейса: `src/pages` — экраны, `src/forms` — модальные формы, `src/components` — общие элементы, `src/lib` — расчёты fees, отчёты и PDF без зависимости от React, `src/state.tsx` — сессия и сохранение данных. Стили — утилиты Tailwind с токенами темы в `src/styles.css`; Preflight отключён, чтобы сохранить исходные отступы браузера.

## Проверки

`npm test` — серверная авторизация, CSRF, сохранение, конфликты, перезапуск базы, команда и восстановление (`tests/*.test.mjs`), а также расчёт fees и снимки отчётов (Vitest, `tests/web`). `npm run test:pdf` — генерация PDF и переполнение; перед запуском установите `npm install --no-save @napi-rs/canvas`.

## Настройки и восстановление пароля

Раздел «Настройки» позволяет задать имя администратора, название организации и год набора для новых карточек. Смена пароля требует текущий пароль и завершает все сессии. В разделе восстановления создайте резервный код и сохраните его отдельно: показывается один раз, в базе хранится только хеш. Новый код отменяет предыдущий. На странице входа «Забыли пароль?» принимает почту, код и новый пароль. Использованный код удаляется, все сессии завершаются. После восстановления создайте новый код. Почтовая рассылка для восстановления не используется; без заранее созданного кода этот способ недоступен.

В карточке → «Тесты» и на вкладке информации можно добавлять результаты и пересдачи IELTS (0–9, шаг 0,5), TOEFL iBT (1–6, шаг 0,5 либо 0–120, целые) и DET (10–160, шаг 5). Хранятся общий балл и необязательная дата сдачи; автоматического пересчёта шкал нет. Новые поля не меняют старые карточки и снимки отчётов.
